# 饮食规划流程

## 复用私人档案

默认私人目录为 `~/.local/share/what-to-eat-today/`，用户配置的位置优先。若同一位已确认用户已有 `~/.local/share/weekly-meals/`，继续使用原位置，避免重新建档；不把私人文件复制进 skill。按需读取 `profile.json`、健康任务所需的 `health-records.json` 和 `plans/` 中近期相关计划。

为另一个人规划时先确定对象，使用独立目录，例如 `profiles/<person-id>/`。多人同餐先满足过敏及医嘱的安全交集，再用可分开的酱料或配菜适配口味。未知值不能解释为没有。

复用已确认信息，一次简短询问真正影响本次任务的缺口。按健康情况交付可执行食谱前，核对过敏、相关药物/补剂和医生饮食要求。等待关键安全信息时，可给明确标注的临时示例或先做时间、设备准备，不宣称已完成临床适配。库存、辣度等可选缺口不必阻止生活方式草稿；已回答的字段不重复问。

相关字段：菜系与代表菜、喜欢和不喜欢的食材；辣、麻、酸、甜分别记录；过敏；医嘱及日期；目标；人数与餐次；预算币种；时间、厨具、冷藏/复热条件；烹饪频率和每批餐数。只有设置适用的营养数字目标时才补充年龄、相关生理信息、身高体重和活动量。明确偏好保持有效，推断待确认，临时点菜只用于这一餐。

## 按请求选择范围

- **今天／一道菜：** 围绕现有食材给做法和有用替换。问鸡腿做法时不用重做七天菜单。
- **带饭／批量：** 明确哪些餐一起做，以及具体做饭时间。午晚餐一起做不等于做两次，也不等于允许一周吃同一道菜。
- **每周：** 标日期、覆盖所需餐次、复用食材，繁忙日安排快捷餐。仅在已授权访问时读取相关日程。

口味要改变候选菜和排序。先过滤安全限制，再按真实偏好、花费、时间和可得性排序，最后平衡多样性。不能从菜系推断辣度、重油重盐或接受全部食材。需要调整时保留菜的核心风味并说明变化，把椒香与油盐用量分开考虑。不默认减重、断食、高蛋白、补剂或所有人都吃同一菜系。

## 把用量写成能操作的食谱

每道菜明确人数、份数、覆盖几餐。重量标明生/熟、可食部，带骨采购量与去骨肉量分开。先写**整锅／整批用量**，再写每餐/每盒分配；油、酱油等调味只计一次。餐数变化时明确缩放，并按锅具、收汁和做法调整时间，不能机械翻倍所有参数。

优先克和 mL，可同时写标准量勺：本 skill 的食谱约定为 **1 茶匙 tsp＝5 mL；1 汤匙 tbsp＝15 mL**。若当地量勺采用其他规格，以标注的 mL 为准。容量与重量分开：5 mL 盐不等于5 g，换算需有可靠的具体食材依据。干料刮平，液体装至勺口；普通餐勺、汤勺、泵头、喷几下都不能当作已知容量，勺子自重与长度也不能证明能盛多少。

用户请求厨具时，适配实际习惯和样式，例如能常放小勺的带盖调料罐、带饭盒、有把手的炒菜油壶或餐桌细口瓶。核对实际商品的容量、尺寸、勺盖配合和材质。原配小勺未标容量时就保留未知；商品标题写橄榄油不代表只限装橄榄油，但仍须按用户要的外形及材质用途选择。没有请求厨具时，不自动把设备加入食材采购。

每餐交付菜名、份量、步骤、主动/总耗时及相近风味替换。营养数字须来自对应标签、已核实食谱或数据库，注明份量基础和不确定性；无数据则定性核对。只规划晚餐不能声称全天达标。

## 采购、带饭与反馈

跨菜合并食材，只扣除已确认可用库存；食谱消耗量与采购包装量、预计结余分开，油盐酱料纳入。按蔬果、蛋白、主食、乳品/替代品、调味分组。实时价格标门店与日期，未查则标粗估。预算明确币种。

安排冷却、冷藏/冷冻、运输、解冻和复热。带饭先核对目的地冰箱、保温运输和复热条件，不能默认常温放到午餐。按健康规则中的储存期限并核对具体食物例外，不默认把整周熟食都冷藏。

清单、加购、下单是分别授权的动作。未被用户纳入的购物车商品保持原状；购买前核对规格、数量、重复项、所选地址/付款方式及含税运费等必要费用后的总额和授权预算。提交结果不明确时先查订单状态再决定是否重试。只有可见订单确认才能记为已购买；购买不等于已吃或正在服药。

计划保存在私人 `plans/YYYY-MM-DD.md`，使用当天日期或周起始日；修改保留旧版。聊天给摘要和文件链接。计划、已订购、已吃分开记录，真实摄入以用户报告为准。确认餐次覆盖、过敏/医嘱、口味、份量与采购加总、时间和储存条件及未解决缺口后，才称为可执行。按具体反馈改进，不把一次点菜或购买推成永久偏好；每周规划不自动设置提醒。
